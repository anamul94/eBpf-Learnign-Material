## 2.1 Why C for eBPF?

eBPF programs are compiled by Clang into eBPF bytecode. The C language is the primary source language because:

1. **The Linux kernel is C** — eBPF interacts with kernel data structures defined in C
2. **libbpf is C** — The standard library for loading eBPF programs is written in C
3. **All kernel examples are C** — Documentation, samples, and production code use C
4. **Clang's eBPF target is mature** — Decades of C compiler optimization apply

But eBPF C isn't standard C. It's a restricted subset with unique constraints. Let's understand both the foundations and the restrictions.

## 2.2 C Foundations — The Essentials

### 2.2.1 Types and Sizes

eBPF cares about exact sizes. Unlike userspace where `int` might be 16 or 32 bits depending on the platform, eBPF requires explicit sizing:

```c
// Standard types — avoid these in eBPF
int x;          // Size varies — DON'T use in eBPF
long y;         // Size varies — DON'T use in eBPF

// Fixed-size types — USE these in eBPF
__s8  a;        // Signed 8-bit
__u8  b;        // Unsigned 8-bit (uint8_t)
__s16 c;        // Signed 16-bit
__u16 d;        // Unsigned 16-bit (uint16_t)
__s32 e;        // Signed 32-bit
__u32 f;        // Unsigned 32-bit (uint32_t)
__s64 g;        // Signed 64-bit
__u64 h;        // Unsigned 64-bit (uint64_t)
```

You can also use standard `<stdint.h>` types:

```c
#include <stdint.h>

int8_t   a;     // Same as __s8
uint8_t  b;     // Same as __u8
int16_t  c;     // Same as __s16
uint16_t d;     // Same as __u16
int32_t  e;     // Same as __s32
uint32_t f;     // Same as __u32
int64_t  g;     // Same as __s64
uint64_t h;     // Same as __u64
```

**Why this matters:** eBPF programs interact with kernel data structures that have fixed layouts. Using `int` instead of `__u32` could cause misaligned reads or incorrect struct field offsets.

### 2.2.2 Pointers — The Heart of eBPF

Pointers in eBPF work like standard C, but with critical restrictions:

```c
// Basic pointer usage — ALLOWED
__u32 value = 42;
__u32 *ptr = &value;
__u32 dereferenced = *ptr;  // This requires verifier approval!

// Pointer arithmetic — RESTRICTED
__u32 arr[10];
__u32 *p = arr;
p = p + 1;                  // Allowed: bounded, within array
// p = p + 100;             // REJECTED by verifier: out of bounds

// NULL checks — REQUIRED
if (ptr != NULL) {
    __u32 val = *ptr;       // Verifier knows ptr is valid here
}
```

**The Golden Rule of eBPF Pointers:** Every pointer dereference must be provably safe to the verifier. This means:
- Pointers must be checked against NULL before dereferencing
- Array accesses must be bounds-checked
- Pointer arithmetic must stay within known bounds

### 2.2.3 Structs — Interfacing with the Kernel

Structs are how eBPF programs interact with kernel data:

```c
// A simple struct for our eBPF program
struct event {
    __u32 pid;
    __u32 uid;
    char comm[16];
    __u64 timestamp;
};

// Using the struct in an eBPF program
struct event *e = bpf_map_lookup_elem(&events, &key);
if (e) {
    e->pid = bpf_get_current_pid_tgid() >> 32;
    e->timestamp = bpf_ktime_get_ns();
    bpf_get_current_comm(&e->comm, sizeof(e->comm));
}
```

**Key points:**
- Struct layout must match kernel structs exactly (for kernel interaction)
- Use `__attribute__((packed))` only when necessary — it can hurt performance
- Always use `sizeof()` for size calculations, never hardcode sizes

### 2.2.4 The Preprocessor — eBPF's Best Friend

The C preprocessor is heavily used in eBPF for conditional code and constants:

```c
// Header includes specific to eBPF
#include <vmlinux.h>        // Kernel types (generated by bpftool)
#include <bpf/bpf_helpers.h> // eBPF helper functions
#include <bpf/bpf_tracing.h> // Tracing helpers
#include <bpf/bpf_core_read.h> // CO-RE read macros

// Constants
#define MAX_ENTRIES 1024
#define TASK_COMM_LEN 16

// Conditional compilation
#ifdef DEBUG
    bpf_printk("Debug: value=%d\n", value);
#endif

// Macros for common patterns
#define CHECK_PID(filter, pid) \
    if (filter != 0 && filter != (pid)) { return 0; }
```

## 2.3 eBPF-Specific C Constraints

This is where eBPF C diverges from standard C. The verifier enforces these rules:

### 2.3.1 No Loops (Unless Bounded)

```c
// REJECTED: Unbounded loop
for (int i = 0; i < n; i++) {  // n is unknown at verification time
    // ...
}

// ACCEPTED: Bounded loop with constant max
#pragma unroll
for (int i = 0; i < 10; i++) {  // Constant bound — verifier unrolls this
    // ...
}

// ACCEPTED: Loop with bounded condition
for (int i = 0; i < 10 && i < max; i++) {
    // ...
}
```

**Why:** The verifier must prove the program terminates. Unbounded loops could hang the kernel.

### 2.3.2 No Global Variables (Use Maps Instead)

```c
// REJECTED: Mutable global
int counter = 0;

// ACCEPTED: Use a map
struct {
    __uint(type, BPF_MAP_TYPE_ARRAY);
    __uint(max_entries, 1);
    __type(key, __u32);
    __type(value, __u64);
} counter_map SEC(".maps");

// Usage:
__u32 key = 0;
__u64 *counter = bpf_map_lookup_elem(&counter_map, &key);
if (counter) {
    __sync_fetch_and_add(counter, 1);
}
```

**Exception:** `const` globals are allowed since they're read-only:

```c
const __u32 MAX_RETRIES = 3;  // OK — immutable
```

### 2.3.3 No Floating Point

```c
// REJECTED
float x = 3.14;
double y = 2.718;

// ACCEPTED: Use integer math
__u32 fixed_point = 314;  // Represents 3.14 with 2 decimal places
```

**Why:** The kernel doesn't save/restore floating-point state. eBPF avoids this overhead entirely.

### 2.3.4 No Variadic Functions

```c
// REJECTED: Variadic functions
void my_printf(const char *fmt, ...);  // Not allowed

// ACCEPTED: Fixed arguments
static void log_event(__u32 pid, __u64 timestamp);
```

**Exception:** `bpf_trace_printk` and `bpf_printk` are special — they're helper functions with special verifier handling.

### 2.3.5 No Function Calls (Except Helpers and Static Inlines)

```c
// REJECTED: Non-static function calls
int helper(int x) { return x + 1; }  // Not inlined — REJECTED

// ACCEPTED: Static inline functions
static __always_inline int helper(int x) { return x + 1; }

// ACCEPTED: Helper functions (provided by the kernel)
__u64 ts = bpf_ktime_get_ns();  // This is a helper call
```

**Why:** eBPF has limited call depth (32 levels max) and all functions must be traceable. `static __always_inline` guarantees inlining.

### 2.3.6 Limited Stack Size

```c
// REJECTED: Large stack allocation
char buffer[1024];  // eBPF stack is only 512 bytes!

// ACCEPTED: Small stack usage
char buffer[64];    // OK — within 512-byte limit

// ACCEPTED: Use maps for large data
struct {
    __uint(type, BPF_MAP_TYPE_PERCPU_ARRAY);
    __uint(max_entries, 1);
    __type(key, __u32);
    __type(value, struct large_event);  // Can be large
} heap_map SEC(".maps");
```

**The eBPF stack is exactly 512 bytes.** This includes all local variables in a program. Exceeding this causes verifier rejection.

## 2.4 eBPF C Patterns

### 2.4.1 Map Declaration Pattern

Modern eBPF uses BTF-style map declarations:

```c
// Array map — fixed-size, indexed by integer
struct {
    __uint(type, BPF_MAP_TYPE_ARRAY);
    __uint(max_entries, 1024);
    __type(key, __u32);
    __type(value, __u64);
} counters SEC(".maps");

// Hash map — key-value store with arbitrary keys
struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 10000);
    __type(key, __u32);
    __type(value, struct process_info);
} processes SEC(".maps");

// Per-CPU map — separate value per CPU (no locking needed)
struct {
    __uint(type, BPF_MAP_TYPE_PERCPU_HASH);
    __uint(max_entries, 10000);
    __type(key, __u32);
    __type(value, __u64);
} percpu_counters SEC(".maps");

// Ring buffer — streaming events to userspace
struct {
    __uint(type, BPF_MAP_TYPE_RINGBUF);
    __uint(max_entries, 256 * 1024);  // 256 KB
} events SEC(".maps");
```

The `SEC(".maps")` macro tells the compiler to place this in the ELF maps section.

### 2.4.2 Program Section Pattern

```c
// The SEC macro defines where the program attaches
SEC("tp/syscalls/sys_enter_execve")
int tracepoint__syscalls__sys_enter_execve(struct trace_event_raw_sys_enter *ctx)
{
    // Program body
    return 0;
}

// Common section names:
// "tp/<category>/<name>"     — Tracepoint
// "kprobe/<function>"        — Kprobe
// "kretprobe/<function>"     — Kretprobe
// "xdp"                      — XDP program
// "socket"                   — Socket filter
// "cgroup/skb"               — Cgroup socket buffer
// "lsm/<hook>"               — LSM hook
```

### 2.4.3 Event Submission Pattern

```c
// Reserve space in ring buffer
struct event *e = bpf_ringbuf_reserve(&events, sizeof(*e), 0);
if (!e)
    return 0;  // Buffer full — skip this event

// Fill the event
e->pid = bpf_get_current_pid_tgid() >> 32;
e->uid = bpf_get_current_uid_gid() & 0xFFFFFFFF;
bpf_get_current_comm(&e->comm, sizeof(e->comm));
e->timestamp = bpf_ktime_get_ns();

// Submit to userspace
bpf_ringbuf_submit(e, 0);
```

### 2.4.4 CO-RE Read Pattern

CO-RE (Compile Once, Run Everywhere) lets you read kernel fields portably:

```c
// Without CO-RE — hardcoded offset (breaks across kernel versions)
__u32 pid = ctx->pid;  // Direct field access — fragile

// With CO-RE — portable field access
struct task_struct *task = (struct task_struct *)bpf_get_current_task();
__u32 pid = BPF_CORE_READ(task, pid);  // Uses BTF to find field

// CO-RE with nested structs
__u64 inode = BPF_CORE_READ(task, mm, exe_file, f_inode, i_ino);
```

## 2.5 The eBPF C Toolchain

### 2.5.1 Compilation Flow

```
Source (.c)
    │
    ▼
Clang -target bpf -O2
    │
    ▼
ELF Object (.o)  ← Contains BTF info, map defs, program sections
    │
    ▼
libbpf (userspace)
    │
    ▼
bpf() syscall → Kernel
    │
    ▼
Verifier → JIT → Attach
```

### 2.5.2 Essential Compiler Flags

```bash
# Basic eBPF compilation
clang -target bpf -O2 -g -c program.c -o program.o

# Flags explained:
# -target bpf      : Generate eBPF bytecode, not native code
# -O2              : Optimize (required for some verifier checks)
# -g               : Include BTF debug info (needed for CO-RE)
# -c               : Compile only (produce .o file)
# -I/path/to/vmlinux.h : Include kernel headers
```

### 2.5.3 Generating vmlinux.h

```bash
# Generate kernel headers from running kernel
bpftool btf dump file /sys/kernel/btf/vmlinux format c > vmlinux.h

# This creates a header with ALL kernel types — essential for CO-RE
```

## 2.6 Common C Mistakes in eBPF

### Mistake 1: Forgetting NULL Checks

```c
// WRONG — verifier rejects
__u64 *val = bpf_map_lookup_elem(&map, &key);
*val += 1;  // What if val is NULL?

// CORRECT
__u64 *val = bpf_map_lookup_elem(&map, &key);
if (val)
    *val += 1;
```

### Mistake 2: Stack Overflow

```c
// WRONG — exceeds 512-byte stack
struct large_event ev;  // If this is > 512 bytes, verifier rejects
char buffer[512];       // Already at the limit!

// CORRECT — use maps for large data
struct event *e = bpf_map_lookup_elem(&event_map, &key);
if (e) {
    // Work with e
}
```

### Mistake 3: Unbounded Loops

```c
// WRONG
for (int i = 0; i < data_len; i++) {  // data_len is dynamic
    // ...
}

// CORRECT — bound the loop
for (int i = 0; i < 256 && i < data_len; i++) {
    // ...
}
```

### Mistake 4: Wrong Types

```c
// WRONG — platform-dependent size
unsigned long timestamp = bpf_ktime_get_ns();

// CORRECT — explicit size
__u64 timestamp = bpf_ktime_get_ns();
```

## 2.7 A Complete Minimal Example

Let's put it all together with a complete, compilable eBPF C program:

```c
// minimal.bpf.c
#include "vmlinux.h"
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_tracing.h>

// Map: count execve calls
struct {
    __uint(type, BPF_MAP_TYPE_ARRAY);
    __uint(max_entries, 1);
    __type(key, __u32);
    __type(value, __u64);
} execve_count SEC(".maps");

// Tracepoint: called every time execve is invoked
SEC("tp/syscalls/sys_enter_execve")
int tracepoint__syscalls__sys_enter_execve(struct trace_event_raw_sys_enter *ctx)
{
    __u32 key = 0;
    __u64 *count;

    count = bpf_map_lookup_elem(&execve_count, &key);
    if (count)
        __sync_fetch_and_add(count, 1);

    return 0;
}

// Required license (some helpers require GPL)
char _license[] SEC("license") = "GPL";
```

Compile and inspect:

```bash
# Compile
clang -target bpf -O2 -g -c minimal.bpf.c -o minimal.bpf.o

# Inspect the result
bpftool prog load minimal.bpf.o /sys/fs/bpf/minimal
bpftool prog show
```

## 2.8 Summary

- Use **fixed-size types** (`__u32`, `__u64`) not `int` or `long`
- **Pointers** must be NULL-checked and bounds-checked
- **No unbounded loops** — use constant bounds or `#pragma unroll`
- **No mutable globals** — use maps instead
- **No floating point** — use integer math
- **No variadic functions** — fixed arguments only
- **Stack is 512 bytes** — use maps for large data
- Use **`static __always_inline`** for helper functions
- **CO-RE** with `BPF_CORE_READ` for portable kernel access
- Always include a **license** section
